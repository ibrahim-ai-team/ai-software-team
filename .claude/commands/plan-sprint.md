# Plan sprint

1. Read the orchestration contract, Agile delivery workflow, Definition of Done, and current project state/backlog.
2. Default to a two-week sprint unless the project state records another length. Ask `product-owner` to confirm priority, `project-manager` (Scrum Master) to identify capacity, dependencies, risk and sequencing, and `tech-lead` to split each selected story into small, path-bounded tasks. Use `agile-planning` and `token-context-cost-management` skills for the plan.
3. Select only Ready stories with clear acceptance criteria; split oversized stories and identify dependencies.
4. For every story record stable ID, goal, owner, scope/allowed paths, dependencies, acceptance criteria, estimate with assumptions, test evidence, and rollback/recovery notes where relevant.
5. Include QA, security, documentation, and delivery tasks—not only implementation.
6. Agree the sprint scope and report the goal, committed scope, out-of-scope items, risks and capacity assumptions to the sponsor. Ask for approval only if the plan changes agreed scope, cost, risk or a deadline. Do not silently expand scope or claim a board was updated without evidence.
